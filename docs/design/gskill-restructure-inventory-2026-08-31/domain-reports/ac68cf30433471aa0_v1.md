# 域一 · 评测域(golden / diff / promote / compare)

## ① 应然

**Effect**：把一次已验证的运行行为钉成回归基线，之后每次运行都能对着它得到一个**可解释、语义唯一**的判决。

**own 概念词表**(本域应独占定义的词)：

| 概念 | 应然唯一定义 |
|---|---|
| `golden case` | 一个 agent node 的期望输出(`expected_output`) |
| `baseline` | 一组 golden case 的集合 + 它的来源 run 血统 |
| `diff` | actual vs expected 的字段级差异列表 |
| `score` | 差异的量化，**单一量纲** |
| `stale` | golden 与当前 schema/形状已经对不上 |
| `promote` | 把一次 run 的输出固化为 golden |
| `seed` | 只填补"没有可用 golden"的节点，不覆盖已有 |
| `compare` | 拿一次 run 对着 baseline 出判决 |

**膜**：`.workspace/golden/&lt;baseline_id&gt;/{baseline.json, cases/*.json, report.json}` 是本域唯一对外的物理契约；HTTP 面是 `/api/skills/{id}/golden*` 与 `/api/skills/{id}/runs/{run}/compare`。

**北极星贡献**：
- *流程可靠可重现* — golden 是回归基线的载体，这是本域的全部意义。
- *engine+AST 核心* — diff/score 的**语义**属 engine；Studio 只应是渲染/HTTP/CRUD 消费者。engine 侧文档自己写死了这条:`docs/engine/mvp1/02-mechanism/05-run-inner/06-golden-eval/baseline.md` §2 「Studio 若继续提供 UI/HTTP，只能消费这个 Engine 户型，**不能反向发明 Studio-only schema**」。
- *去黑盒* — 判据(pass/fail/stale/score)必须能解释到字段。
- *本地=服务端* — 同一份 baseline，headless 与桌面得出同一判决。
