# 设计文档三轴模型(总纲)

> 任何 spec-driven 项目的设计文档,是同一系统在**三条正交轴**上的投影。本文是 `design-doc-standards/` 的心智总纲;写作规范 [`01`](./01-writing-standard.md) / 审计规范 [`02`](./02-audit-standard.md) 按这三轴办事。

## 三轴抽象

### 轴① Workflow(决策脊柱 + 留底)
- **主用途**:用户 / 设计者**依次决策设计**的轴线(最接近交互顺序);设计阶段从这走、**保证不漏**。
- **形态**:按旅程**分割单元**,每单元列**原子动作(atom action)**;每个原子动作 → 涉及哪些能力模块 → 在那做决策。
- **决策留底**:PM 决策原话在此留一份底(决策来源档案);**独立、不被依赖**(决策原话已就近落到能力模块)。

### 轴② 能力模块(代码对齐 + 自包含 SSOT)
- **主用途**:最接近代码写作,**切分与代码路径一一对齐**;`baseline`+`alignment` 落点。
- **自包含 SSOT**:实现规范 **+ 就近写 PM 决策原话**——读它就够、含"为什么",不用跳转。

### 轴③ 设计单元(横切映射枢纽)
- **主用途**:从①②**抽象**的横切单元,用于**审计交叉检验 + 对外对接**。
- **形态**:一个 workflow 单元的 atom action 聚合 = 一个设计单元;它涉及的能力模块 = 它的 `spans`。
- **载体 = INDEX**:登记映射,**不重述实现 / 决策**。

## 三轴传动(atom action 是齿轮)
```
PM 决策(workflow atom action,留底)
        │ 沉淀
        ▼
能力模块(实现 + 就近决策原话 = 自包含 SSOT)
        │ 抽象
        ▼
设计单元(INDEX 登记:横跨哪些模块切面 + 锁)
```
> 一个 workflow 单元的原子动作**聚合** = 一个设计单元;原子动作涉及的能力模块 = 该单元的 `spans`。

## 三类真理(SSOT 分类,各管各、不矛盾)
| 真理 | SSOT 在哪 | 说明 |
|---|---|---|
| **实现规范**("怎么做") | **能力模块**(不重复、分切面 owner) | R1 唯一真理只管这个 |
| **决策原话**("为什么") | **能力模块就近 + workflow 留底** | 刻意冗余:隐含假设护栏,**防 AI 自以为是 / 误解**;不算违反 R1 |
| **横跨 / 锁 / 追溯映射** | **INDEX(轴③)** | 不持实现 / 决策,只记映射 |

## 引用拓扑(防 drift)
- **能力模块自包含**(实现 + 决策原话),读它就够、不跳。
- **轴② 内直接双向**:`baseline↔alignment` 配对、能力模块间实现引用、`代码↔baseline`。
- **横跨 / 锁** 登记在 INDEX(轴③);三轴文件只标"属于哪个单元";workflow 留底独立。
- **不搞跨轴两两互引**(决策就近 + INDEX 枢纽已够)。

## 所有权不变量(灭重叠)
- **实现规范**:一个切面只在一个能力模块 owner 写;别处写同切面 = 重复违规(INDEX 的 模块×切面 一眼照出)。
- **决策原话**:能力模块就近 + workflow 留底(**刻意**),非重复违规。
