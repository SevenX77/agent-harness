## 1. 第一性原理:三场景的共同根因

三个场景(S1 哈希自愈 / S2 物料上传 / S3 正则批处理)是同一缺陷的三个症状:

> **`.workspace` 文件 I/O 边界缺一份"类型化 + 事务化 + 冲突感知"的契约。**

- S1 = 缺**冲突恢复**契约;S2 = 缺**安全写入**契约(路径/大小/类型);S3 = 缺**输入类型**契约(JSON vs raw)。
- `workspace-fs` 平台文档明确把文件级语义甩给 Engine/编辑器,平台层无 hash/冲突契约 → 每个 feature 各自手搓。

## 3. 架构决策(2026-06-01,用户确认)

### 决策 1 — S1 用**服务端原子端点**(非客户端自愈)
- 新增 `POST /api/skills/{skill_id}/phases/{phase}/overwrite-whitelist`,body `{field}`。
- 服务端 read → parse frontmatter → 向 `allow_sequential_overwrite` 数组**幂等集合并入**(`addSequentialOverwriteField` 的服务端等价)→ 原子写。
- 该操作**客户端不碰 hash → 不再 403**。乐观锁只保留给自由文本编辑器保存。
- 理由:403 锁死本质是"把加法字段变更当成不透明整文件覆盖"产生的人造问题;服务端原子化直接消除它。

### 决策 2 — S1 **抽成独立平台契约**,skill-lifecycle 只留 S2+S3
- 新建 file-versioning / workspace-IO 冲突契约 spec,定义:canonical hash(复用 `_graph_content_hash`)、原子写、带恢复 UX 的乐观并发(**复用 `ConflictDialog`**)、加法型结构化变更的服务端 read-modify-write 模式(决策 1 即其首个实例)。
- skill-lifecycle 收敛为**批量语料摄取**(S2 上传 + S3 正则映射 + 批处理),内聚的用户叙事。
- 理由:S1 是平台级并发问题,埋在 feature 里会让下个写文件功能重复踩坑;改动散落 skills.py/test_inputs.py/run_manager.py 3 个不相干服务 = 拆分信号。

### 决策 3 — 引入 test input `kind: "json" | "raw"` 判别,贯穿 API/UI/批处理
- `TestInputMetadata` 加 `kind`;list glob 放宽到 `*` 但按扩展名/内容打 kind 标签。
- UI 分区:"Raw Materials" vs "JSON Inputs";raw 只能走 pipeline(S3),**不能直喂老 JSON 批处理**。
- `_load_test_input` / 老批处理路径只接受 kind=json。
- 理由:彻底堵死 `JSONDecodeError` 崩溃 + 前端 "No JSON inputs" 混淆。

## 4. 仍需在 design/impl 落实的工程项(无需再决策)

**S1(迁入新平台 spec)**
- 改 `research.md` 的"追加"措辞 → 明确为结构化幂等并入;若保留前端"Force Overwrite",后端需**显式 `force: bool`**(勿用 expected_hash=None 混淆语义);自愈/重提需**有界重试**防 TOCTOU 再竞争。
- 回答:通用编辑器保存的冲突恢复是否一并复用 ConflictDialog。

**S2 物料上传**
- 上传文件名**必须复用 `validate_skill_file_path`**(防路径穿越)。
- 加文件大小/数量/总量上限 + content-type 校验;定义非 UTF-8 拒绝/降级策略。

**S3 正则批处理**
- **dry-run/预览**:先 materialize 出输入行 + 报告 匹配/排除/未命中 文件,用户确认后再发 N 个 run(防 LLM 成本失控)。
- 禁止静默跳过(未命中必须上报 + WARNING 日志)。
- schema 感知的类型强转 + 校验 `graph_property` 存在于技能输入 schema。
- 抽取逻辑拆成独立 materializer 模块(与 run 执行解耦,可单测/预览)。

**流程/质量**
- 需求改 EARS 格式;补 design.md + tasks.md 后再置 "Implementing"。
- 测试计划:并发竞态 / 路径穿越 / 正则映射(TDD)。
- 错误处理 + 可观测性规格(自愈重试、上传失败、正则未命中均需可观测日志)。
- 向后兼容说明:glob 放宽、`BatchRunRequest` 加字段。
