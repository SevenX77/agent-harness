## ① 应然:Effect / own 概念词表 / 膜 / 北极星贡献

### Effect(一句话)
**让作者用画布拖、用表单填、用编辑器写,三条路改的是同一份磁盘上的 gskill 源文件;比手写 markdown 快、且不会写出编译不过的东西。**

### own 的概念词表(本域是唯一权威)

| 概念 | 含义 | 应然 owner |
|---|---|---|
| `编辑面`(editing surface) | 画布拓扑 / Properties 表单 / Monaco 文本,三个投影 | 本域 |
| `草稿`(draft/dirty) | 未落盘的内存修改 + 其脏标记 | 本域 |
| `落盘`(settle) | 草稿 → 磁盘真相的一次原子写 | 本域 |
| `期望哈希`(expected hash) | 乐观并发凭据 | 本域(判定归 tauri/backend) |
| `保存冲突`(save conflict) | 409/HashConflict 后的四选决策 | 本域 |
| `相位身份`(phase identity) | phase id 与其文件/目录/依赖引用的绑定 | 本域(**格式由格式域定**) |
| `字段白名单` | 按 phase kind 允许编辑的 frontmatter 字段集 | 本域(**字段集由格式域定**) |
| `拓扑写回` | 画布交互 → depends_on/output 变更 → GRAPH.md | 本域 |

### 膜(边界外的,本域只引用不复制)

- **格式域(engine)**:`GRAPH.md` 序列化器、skill 语法/字段集、`F-v3-*` 错误码、subgraph path 解析、phase id 字符类。设计源已明文:`docs/studio/mvp1/README.md:23-27`「engine 拥有的契约……**不在 studio 复制**」。
- **编译/lint 域**:诊断的产生。本域只消费投影。
- **执行域**:run/predict/resume/compare/golden。
- **工作台/文件域**:目录树、文件 CRUD 原语、file-watcher。
- **委托域(copilot)**:agent 写文件 + checkpoint 撤销。

## ③ 账实不符

### ③-1 【重】「409 → 四选对话框」只对三分之一的编辑面成立;另两面各有一套私货策略

设计源明文 `docs/studio/mvp1/02_capabilities/conflict-overwrite/mvp1-alignment.md` F1:「every save includes an expected hash; mismatch **opens a conflict flow rather than replacing remote content**」,**Status: live**。实测四种策略:

| 面 | 409 处理 | 坐标 | 用户看到什么 |
|---|---|---|---|
| Monaco | → `onConflict` → `setConflict` → 四选 Dialog ✅ | `LazyMonacoPanel.tsx:103-115` → `WorkspaceEditorOverlay.tsx:51` → `Workspace.tsx:2479` → `ConflictDialog.tsx:22` | 四选 |
| Properties(phase) | **静默把表单重新贴到远端内容上、用远端 hash 重试** | `PropertiesPanel.tsx:654-677` | **成功时什么都看不到** |
| Properties(GRAPH.md) | 同上 | `PropertiesPanel.tsx:489-512` | 同上 |
| 画布拓扑 | 抛出 → toast | `Workspace.tsx:2121-2131` → `GraphCanvas.tsx:2175/2278/2341/2366/2429` | **`"Request failed with status code 409"`** —— `graph-edit-problem-message.ts:29 graphEditErrorMessage` 对非 `GraphEditError` 直接返回 `error.message`,axios 的默认文案就是这句;拖的那根边被回退 |
| runtime_config PUT | 无 expected_hash,根本不检测 | `api/client.ts:886/972` | 后写者赢 |

**结构性根因**:`WorkspaceContext.tsx:37-44` 的 `SaveConflict` 把 `side: EditorSide` 定成**必填**。画布和 Properties 的冲突没有 editor side,类型层面就进不了这个对话框。ConflictDialog 的四个动作(`handleUseRemote:2213` / `handleViewDiff:2234` / `handleOverwriteRetry:2255`)全部按 `activeFileDetails[conflict.side]` 操作,也确实只服务编辑器 buffer。

&gt; 这条同时否掉了「并发冲突不吞改动」这半条应然:画布的改动被吞掉换成一句 axios 原文,Properties 的改动虽然做了字段级重贴(不算丢),但**决定权没有交给用户**。

### ③-2 【重】相位改名把 node 键的运行期数据全部变成孤儿

`docs/studio/mvp1/03_regions/properties/mvp1-alignment.md` F5 明确要求:「**节点改名 → runtime_config key 同步迁移**」。

实测:`Workspace.tsx:1947-2096` 做了三处同步,**没有第四处**。`grep -rn "rename" apps/studio/backend/app/{services,routers}/*.py | grep -i "node\|phase"` 零命中——后端也没有。改名后失联的数据:

- `.workspace/runtime_config.json` → `llm.compare_candidates.nodes.&lt;node_id&gt;`(`backend/app/services/compare_candidates.py:20-31`)

### ③-3 「实时 lint 行内呈现」只有 Monaco 一面

`useDebouncedLint`(`hooks/useDebouncedLint.ts:127`)把**未保存的 draft** POST 给 `/lint`,只有 `LazyMonacoPanel.tsx:292` 一个调用点;marker 由 `lint-monaco-markers.ts:36 applyLintMarkers` 打进 Monaco model。

### ③-4 Monaco 的写路径不走 Workspace 的写闸门

创作域的**结构**(纯模块外抽、词表单 owner、诊断投影单 owner、golden 负向边界带锁测试)比它的**行为**健康得多。真正的窟窿集中在三处:**三个编辑面各自发明了一套并发策略**(其中两套静默)、**改名只同步了它知道的三个地方**、以及 **PropertiesPanel 里塞着 1000 行不属于本域的运行期配置**。而线索里怀疑的 checkpoint 四命令并没有断线——**断线的是创作域自己:它是全 app 唯一一个能改磁盘、却没有撤销的域。**
