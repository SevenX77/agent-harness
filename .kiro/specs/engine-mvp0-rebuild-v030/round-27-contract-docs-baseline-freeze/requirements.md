# Requirements: Contract Docs Baseline Freeze

## 1. Context (背景)
随着引擎重构不断深入，为防止后续迭代导致架构腐化或功能丢失，必须将现有的核心功能、API 接口和格式标准沉淀为“不可动摇的黄金原则基线”。本轮次 (Round 27) 旨在通过输出三类“契约文档”并辅以工程化机制，为整个引擎确立长期的合规准绳。

在此前的架构规划中，曾错误地将契约边界仅等同于 `__all__` 导出的 18 个符号。但经过对下游消费者（Apps / Scripts）的全面清查，发现 Studio 实际上**实质依赖了 61 个符号**（包括私有的 `_predict_internal` 模块与深层 callback/manifest 模型）。因此，契约的完整性必须基于**“实际消费表面（Actual Consumption Surface）”**重新定义。

## 2. PM's Golden Principle (不可动摇的核心原则)
本 PR 的所有设计和输出，必须绝对服从以下 PM 原始指令（逐字引用）：
> "做任何架构优化也好，代码优化也好，功能一个都不能少！这是原则，API接口也是，说好开放哪些接口，什么功能，一个都不能少，这是黄金原则，不可动摇。你先把手头阶段性任务收尾，立马开一个pr，写清楚功能、api文档，加上之前定下的graph skill的文件标准，这是随便什么任务都不允许违背和修改的，不管改什么都必须最终对齐回去。除非我说要调整这几个文档。"

## 3. Goals (核心目标)
1. **明确功能基准**：建立首份引擎全量核心功能的细颗粒度清单，并将其转变为“可追溯性矩阵 (Traceability Matrix)”，每一项功能必须与自动化测试强制绑定。
2. **规范 API 契约（基于真实消费）**：补齐 61 个实际被下游消费的 API 符号契约（含类型字段级防御），彻底堵死隐性漂移。
3. **冻结文件标准**：通过哈希锁 (Hash Lock) 等强一致手段将现有的 14 份 `skill-spec` 文档状态彻底冻结，作为 Skill 编写和读取格式的绝对真理。
4. **实施全套强制守门 (Enforcement Gate)**：以测试断言、文件校验、显式豁免机制 (Exemption) 落地契约，彻底消除"纸老虎"风险。

## 4. Non-Goals (非目标 - 边界约束)
- **绝对不修改 `skill-spec` 现存规范的正文**：仅允许添加冻结声明相关的 Frontmatter 或顶部系统指令，绝不改写内容。
- **本 PR 不进行业务代码重构**：即使发现了 `_predict_internal` 私有符号泄漏的已知技术债务，**本 PR 也必须只做“现状冻结”而不做代码重构**（重构与解耦将在后续独立的 PR 中进行）。
- **非引擎规范不作强契约**：例如 `docs/engine/` 下除 `skill-spec` 以外的诸如逻辑讲解类文档不属于强契约。
