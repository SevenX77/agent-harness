# Requirements: Contract Docs Baseline Freeze

## 1. Context (背景)
随着引擎重构不断深入，为防止后续迭代导致架构腐化或功能丢失，必须将现有的核心功能、API 接口和格式标准沉淀为“不可动摇的黄金原则基线”。本轮次 (Round 27) 旨在通过输出三类“契约文档”并辅以工程化冻结手段，为整个引擎确立长期的合规准绳。

## 2. PM's Golden Principle (不可动摇的核心原则)
本 PR 的所有设计和输出，必须绝对服从以下 PM 原始指令（逐字引用）：
> "做任何架构优化也好，代码优化也好，功能一个都不能少！这是原则，API接口也是，说好开放哪些接口，什么功能，一个都不能少，这是黄金原则，不可动摇。你先把手头阶段性任务收尾，立马开一个pr，写清楚功能、api文档，加上之前定下的graph skill的文件标准，这是随便什么任务都不允许违背和修改的，不管改什么都必须最终对齐回去。除非我说要调整这几个文档。"

## 3. Goals (核心目标)
1. **明确功能基准**：建立首份引擎全量核心功能的细颗粒度清单，任何重构必须以此逐条对齐。
2. **规范 API 契约**：补齐面向宿主集成方（如 Studio 后端）的 18 个公开 API 的契约文档。
3. **冻结文件标准**：将现有的 14 份 `skill-spec` 文档状态彻底冻结，作为 Skill 编写和读取格式的绝对真理。
4. **工程化落地防御**：通过 CI 测试与文件级标记，确保上述三种基线不可随意漂移或篡改。

## 4. Non-Goals (非目标 - 边界约束)
- **绝对不修改 `skill-spec` 现存规范的正文**：仅允许添加冻结声明相关的 Frontmatter 或顶部系统指令，绝不改写内容。
- **不重构或修改现有代码实现**：本轮次仅作“契约文档补充与防御测试补齐”，不涉及业务代码重构。
- **不覆盖 Studio / 前端的行为规范**：目前仅聚焦 Graph Agent Engine 及相关的核心能力。
