# Specification: studio-feature-skill-lifecycle (Requirements)

> **状态**: 收敛重写 (2026-06-01) —— 替代本文件先前的三场景版本(403 自愈 / multipart 上传 / 正则管道)
> **运行环境**: 本地单用户 Tauri 桌面应用(前端 webview + Python sidecar @ `:8787` + Rust 原生层)
> **设计**: 见 `design.md`

---

## 1. 语义范围 (Scope)

本规格收敛为单一内聚语义:**技能的「测试输入管理 + 批量运行」**。

**范围内**:测试物料(测试输入)的导入 / 列出 / 删除;触发单次与批量运行;统一命名序列文件的自动批量。

**范围外(移交)**:
- 覆盖白名单保存的哈希 403(原 S1)→ 移出,作为独立本地小修(见 `design.md` §5 / DEF-011)
- 文件标准化 / 格式转换工具 → 引擎内置 tools(`packages/graph-agent`)
- 画布渲染 / 节点 / 覆盖检测 → `canvas-topology`
- 工作区文件树展示 → `asset-explorer`
- 技能创建 / 编译 / 生命周期阶段叙事 → 现有 `skills.py`(稳定) / `docs/studio/01_workflows/`

**改名建议(待确认)**:目录名语义过宽,建议改为 `studio-feature-test-inputs-batch`。

## 2. 需求 (EARS)

### 需求 1:测试物料导入(原生路径,非网页上传)

- **R1.1** 当用户在测试输入面板点击"导入"时,系统应当通过 **Rust 原生文件/文件夹选择对话框**让用户选择本地文件或文件夹。
- **R1.2** 当用户在对话框确认选择后,系统应当把所选**路径**交给 Python sidecar,由其将文件读入/拷贝进该技能的 `.workspace/test_inputs/` 目录(非 multipart 文件流)。
- **R1.3** 系统应当支持非结构化文本物料(`.md` / `.txt`)与结构化输入(`.json`)。
- **R1.4** 系统应当列出 `test_inputs` 目录下的物料,并展示文件名、大小、修改时间等元数据。
- **R1.5** 当用户删除某个物料时,系统应当从 `test_inputs` 移除该文件并刷新列表。
- **R1.6** 当文件名包含异常路径片段时,系统应当复用既有安全路径校验,拒绝写到目标目录之外(本地环境,定位为**健壮性**而非安全防护)。

### 需求 2:物料与结构化输入的区分(防崩)

- **R2.1** 系统应当为每个测试输入标注类型(结构化 `json` / 原始物料 `raw`),最简实现可按扩展名判定。
- **R2.2** 如果某个输入是原始物料(非 JSON),那么系统**不应当**将其直接送入仅接受 JSON 的运行装载路径(`_load_test_input`)。
- **R2.3** UI 应当将"原始物料"与"JSON 输入"**分区呈现**,避免混淆。

### 需求 3:批量运行

- **R3.1** 当用户选择多个测试输入并触发批量运行时,系统应当对每个输入**各发起一次运行**(一输入一运行)。
- **R3.2** 当导入的文件呈现明显的统一命名序列(如 `chapter1`、`chapter2`…)时,系统应当识别该序列并**建议自动开启批量模式**,默认运行数量 = 文件数量。
- **R3.3** 系统应当**假定导入的序列物料格式/命名是统一规整的**;不为脏数据设计复杂解析(脏数据由用户上游规整,或经引擎内置转换工具处理)。
- **R3.4** 当批量运行中某个输入失败时,系统应当**显式报告失败项**,不静默跳过。

### 需求 4:本地环境基线

- **R4.1** 本特性面向**本地单用户桌面环境**;不引入面向多租户服务器的安全 / 限流 / 并发冲突机制。

---

## 3. 非目标 (Non-goals)

- 不做哈希冲突三方合并 / 文件版本平台契约(原 S1 降级为独立本地小修)。
- 不做网页式 multipart 上传(改为原生选路径 + Python 读入)。
- 不做正则映射管道 / 强制 dry-run / 类型强转引擎。
- 不做文件格式转换工具(归引擎内置 tools)。
