# 长流程 iterate 流水线失败场景全清单（Failure Taxonomy）

> **性质**: reference（参考清单，非 FROZEN 基线）
> **来源**: 2026-06-10 story-deconstruction mvp1 改写讨论。PM 拍板失败策略 abort 后，对"哪些失败能自动修复、哪些不能"的系统盘点；经 Gemini 架构评审查漏纠错两轮，Claude 收敛。
> **关联设计**: [02-iterate](../mvp1/02-mechanism/04-run-outer/02-iterate/mvp1-alignment.md)（声明式循环）· [03-checkpoint](../mvp1/02-mechanism/04-run-outer/03-checkpoint/mvp1-alignment.md)（断点续跑）· [05-exit-control](../mvp1/02-mechanism/05-run-inner/05-exit-control/mvp1-alignment.md)（退出闸）
> **典型负载**: 100 章小说解构（并发分段 → 时间线缝合 loop → 几十批分析 loop → 全书综合），运行数小时。

## 0. 判定原则

**失败能否自动修复，只看一条：失败是不是确定性的。**
- 瞬时性失败（再试一次结果可能不同）→ 自动修复。
- 确定性失败（重试一万次结果一样）→ 自动修不了，因为要改的东西（数据 / skill 定义 / 配置 / 环境）不在引擎手里。

失败策略已定稿（PM 2026-06-10）：**abort 是默认且唯一的自动策略**（停下、完整存档、修复后从断点续跑），引擎不自动跳过任何一项；"跳过"只能是人在续跑入口的显式操作（后果自担）。

## 1. 引擎五层自动防线（由内到外）

| 层 | 职责 | 处理的失败 |
|---|---|---|
| L1 网关层 | 单次 LLM 请求 | 网络抖动 / 限流 429 / 5xx → 重试 + 模型 fallback 链 |
| L2 agent loop 回灌 | LLM 输出格式 | 结构化解析失败 → 错误结构化回灌 LLM 自我修正 |
| L3 validator + nudge | LLM 输出质量 | 业务校验不过 → nudge 提醒重试（扣 max_iterations） |
| L4 退出闸 | phase 完结性 | agent 停止但未提交合格 finish_task → 强制拉回；耗尽则显式失败（**phase 不静默成功**） |
| L5 iterate 宏观 retry | 复合型崩溃 | API 大面积波动把内层重试短时间打光 → 间隔后整项重试（可选，默认 0 次） |

## 2. 第一档：全自动修复（用户无感）

| # | 场景 | 防线 |
|---|---|---|
| 1 | 单次请求网络抖动 / 限流 / 服务器 5xx | L1 |
| 2 | LLM 输出格式不合格（解析不出结构化结果） | L2 |
| 3 | LLM 输出内容不过业务校验器 | L3 |
| 4 | agent 跑完未提交最终产出 | L4 |
| 5 | API 短时大面积波动（内层重试被打光） | L5 |

## 3. 第二档：半自动（自动 abort 存档，条件恢复后续跑即可，零数据损失）

| # | 场景 | 备注 |
|---|---|---|
| 6 | 长时间 API 服务事故（L5 也耗尽） | 服务恢复后从断点续跑；studio 可做"定时探测 + 自动续跑"进一步自动化 |
| 7 | 进程被杀 / 机器重启 / 断电 | **前提：checkpoint 写入必须原子**（事务式落盘），写一半断电不得留下损坏档案 → 引擎验收要求 |
| 8 | 账号瞬时问题（临时欠费充值后） | 续跑即可 |

### 4f. 状态类（Gemini 评审补充，已采纳）
| # | 场景 | 备注 |
|---|---|---|
| 24 | **累积台账膨胀**：loop 后期实体台账大到撑爆 LLM 上下文窗口 | 要人定台账摘要/裁剪策略 → 设计反馈：accumulate 需体积治理 |

## 5. 第四档：最隐蔽——系统认为"成功"、业务上是错的（不触发任何失败机制）

| # | 场景 |
|---|---|
| 27 | LLM 输出过了所有校验但内容是幻觉（张冠李戴） |
| 28 | 累积台账语义污染（同一实体重复注册、别名未合并），下游全部继承 |
| 29 | 语义回退：loop 第 50 轮推翻第 10 轮的定论，错误指数放大 |

防线不是失败处理，而是质量机制：validator 覆盖度、golden 集回归评测、人工抽检。
设计原话（05-exit-control）：**"系统不能保证 LLM 一定把任务做好；能保证的是 phase 不会静默成功。"**

## 6. 评审中被拒绝的建议（记录决策，防止回潮）

| 建议 | 拒绝理由 |
|---|---|
| io 契约漂移做"弱类型降级 / 默认值填充"容错 | 制造静默失败，与零容忍静默降级铁律正面冲突；契约对不上就该响亮地炸 |
| 重试多次失败后自动下调 validator 阈值、打 low_confidence 标签放行 | 自动降质量标准 = 静默降级；质量不达标停下等人裁决 |

## 7. 采纳为可选项的建议（记入设计反馈，非本期必做）

| 建议 | 说明 |
|---|---|
| 模型升级重试（escalation） | 同模型重试 N 次不过 → 自动切更强模型再试，作为 L3/L4 与 abort 之间的可选层 |
| Token 熔断线 | 单 phase 消耗超预算（如金额阈值）强制停下转人工，防止重试循环烧钱 |

## 8. 汇总：本轮新增的引擎侧反馈

1. checkpoint 写入原子性（验收要求，支撑场景 7）
2. 续跑版本漂移检测（验收要求，场景 25）
3. iterate per-item 超时声明（设计反馈，场景 26）
4. accumulate 体积治理（设计反馈，场景 24）
5. 模型升级重试 + token 熔断（可选项，§7）
