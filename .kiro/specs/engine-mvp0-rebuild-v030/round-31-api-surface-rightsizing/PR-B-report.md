PR-B 要解决的是“引擎把一次运行的文件写到哪里、谁来决定这个位置”这件事。之前规则不够统一：有些文件按调用方给的位置走，有些预测结果有一个顶层特例目录，调用方也可以不明确指定工作目录，结果就是一次运行的东西可能散在不同地方，后面要找、要清理、要给 Studio 展示都容易混乱。PR-B 定下的新规矩是：以后调用引擎跑技能时，必须先给一个明确的工作目录，而且这个目录必须是完整地址；引擎每跑一次，就在这个工作目录下面建立一个按运行编号区分的文件夹；一次运行的执行轨迹、结果、最终状态、指标、副产物这 5 类东西都放进这个文件夹里；原来预测结果那个顶层特例目录废掉，预测和真实运行走同一套收纳规则。

实现按这个设计完成了。现在没有明确工作目录就不能跑；工作目录不是完整地址也会被拦住；每次运行都会落到自己的运行编号文件夹；预测结果不再走旧的顶层特例目录；没有单独指定名字的副产物会自动进入本次运行自己的副产物区域。证据上，引擎全套测试 1226 项通过、0 失败；Studio 354 项通过；Gateway 22 项通过。a3 审计也核对了 10 份相关说明文档，结论全部通过，旧描述扫描干净，没有误碰不该碰的冻结契约。中途确实出现过“多处失败”，但排查后确认是测试环境的临时缓存位置只读造成的假失败；换到可写权限重跑后，结果变成 0 失败。另有一处对外约定文档需要跟随这次已批准的变更更新，这是 PM 已经明确同意的事项；流程是先批准，再记录治理豁免，再修改，再重新锁定指纹，最后测试通过；a3 也独立核对了新指纹，结果完全匹配。

做完之后，从使用者视角看，跑一个技能会很容易理解：磁盘上会出现一个“运行编号文件夹”，这就是本次运行的全部包裹。里面的执行轨迹文件记录过程里发生了什么；结果文件记录这次运行交回给调用方的结果；最终状态文件记录结束时留下的完整状态；指标文件记录耗时、计数等可观察信息；副产物文件夹放运行中额外生成的材料。Studio 这类对接引擎的应用，以后只需要按运行编号去拿这一整包东西，不再需要额外寻找预测专用目录，也不再需要记住哪个结果写在旧的顶层特例位置。
