# Agent 节点 Prompt 设计

agent 节点的 prompt 不是聊天提示词，是**数据管道里的一段变换**：输入吃上游 io，输出必须严格落进本 phase 的输出 schema，还要经得起 golden eval 打分。

## 结构模板（按序五段）
1. **角色与任务**：一句话定位（"你是 X，把 A 变换成 B"），不堆背景故事。
2. **输入说明**：逐字段解释上游给了什么、哪些字段是判断依据、哪些只是上下文。
3. **任务分解**：把变换拆成可核查的步骤；有判断标准的写成显式规则（"满足 X 才算 Y"），不留给模型自由发挥。
4. **输出格式**：严格对齐本 phase 输出 io schema——字段名、类型、嵌套逐一写死；给一个**完整的输出示例**。
5. **约束与拒绝路径**：输入异常/信息不足时输出什么（明确的空值约定，而不是让模型自己编）。

## Golden 对齐
- 写 prompt 前先想 golden 怎么打分：**输出里每个字段都应该是可比对的**（稳定枚举/结构化值优于自由文本）。
- 自由文本字段是 golden 不稳定的最大来源——能枚举就枚举，必须自由文本的字段控制长度并规定口径。
- 温度类波动靠输出结构消化，不靠"请保持一致"这类空话。

## 迭代方法
1. 用真实上游数据 Predict 跑一轮，对着实际输出改 prompt，不凭想象改。
2. 一次只改一个变量（某条规则/某个字段说明），改完重跑对比。
3. 失败样本沉淀成 prompt 里的显式规则或反例。

## 反模式
- ❌ 输出 schema 靠"请输出 JSON"一句话带过（必须逐字段写死+示例）。
- ❌ prompt 里复述上游整段数据（引用字段名即可，数据引擎会注入）。
- ❌ 让模型"自行判断合适的格式/数量"。
- ❌ 用礼貌性语气词填充（每一句都应改变模型行为，删掉不影响输出的句子）。
