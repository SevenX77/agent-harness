# 并发推进 SOP(多 agent 编排交付)

> 本文件是**协调方会话用多个实施 agent 并行推进一批工单**时的规则源:席位怎么编、
> 工单什么时候放行、怎么隔离、任务书写什么、PR 怎么审怎么合、状态落在哪。
> 它不改变 [AGENTS.md](../../AGENTS.md) 的任何工程规则——每张工单落地仍走
> AGENTS.md 的 worktree→PR→CI 管线与「CI Gates」门禁清单(本文**引用不复制**,
> 按「文档事实唯一所有权」);本文只规定"同时跑很多张工单"这件事额外生效的纪律。
>
> **适用范围**:由一个协调方会话派发、多个实施 agent 并行执行的程序性交付
> (例:2026-08/09 的 gskill 重整七批工单)。单人单任务的日常开发不需要本文,
> 直接走 AGENTS.md 与 `apps/studio/frontend/CLAUDE.md`。
>
> **多 agent 编排的另一条路线**是 ah 编队(`.ah/README.md`);本文描述的是
> 协调方直接用会话内后台 agent 派单的轻量形态,两者不互斥,按任务规模选。

## 一、席位编制(资源方案)

资源方案的批准记录在
[gskill 重整决议](../design/gskill-restructure-decision-2026-08-31.md)
(用户批准的「资源与实施方案」);本节是其操作口径。

| 席位 | 型号/档位 | 只做什么 | 绝不做什么 |
|---|---|---|---|
| 协调方(主会话) | Fable,xhigh | 推导/裁决、拆工单 DAG、写任务书、审核裁定、合并、落盘 | 写产线代码;与在跑工单碰同一文件 |
| 实施席(后台 agent) | Opus,xhigh | 一张工单从 TDD 到 PR 全程;返修回原席 | 越出任务书领地;自行合并;代裁原则问题 |
| 交叉审 | codex GPT-5.6-sol,xhigh | 对 PR delta 的对抗式审查,给 approve/rework + 分级发现 | 终裁(它的发现须经协调方裁定真伪) |

codex 调用配方(命令行,只读全盘):

```bash
codex exec --skip-git-repo-check -c model="gpt-5.6-sol" \
  -c model_reasoning_effort="xhigh" \
  -c 'sandbox_permissions=["disk-full-read-access"]' \
  --output-last-message <裁决输出文件> - < <提示词文件>
```

## 二、调度(什么时候放行)

1. **先摆 DAG 再开工**:全部工作摆成带依赖的工单图。依赖只认两种——
   **裁决依赖**(等用户裁决/等方案批准)与**文件依赖**(与在跑单碰同一片文件)。
   "概念上有先后"不是依赖(呼应 Workflow 里 pipeline 优于 barrier 的同一判断)。
2. **放行铁律:任何放行门一开,立即扫全 DAG,把所有零文件冲突的工单一次拉满。**
   不排队、不等上一批收尾。依据是实证教训(2026-09-01):批B 的放行门在 00:24
   打开,协调方却等手头修缺陷批收尾后 ~07:50 才派单,损失约 7 小时并行进度——
   而那一波工单与在修的缺陷零文件重叠,本可即刻并行。
3. **重叠面大的工单不硬并行**:与多张在跑单共享大片文件(如全量测试语料改造)
   的单,压着等清场,代价是等待,收益是零 rebase 混战。
4. 本机并行上限以资源实测为准(2026-09 实测 8 个 agent 并行可行);瓶颈是
   CPU/磁盘而非模型——多套测试套件同跑会把毫秒级时序测试挤成假红,见第五节第 4 条。

## 三、隔离(怎么不撞车)

1. **一单一 git worktree,绝不在主检出树干活**。主仓用 `scripts/wt-new.sh`;
   其他仓用 `git worktree add <独立目录> -b <分支> origin/main`。
2. 任务书里**明令不碰**:别人的 worktree、封存分支、以及与在跑单重叠的文件区域。
3. 两单必须碰同一文件时,任务书写死**合并顺序与 rebase 责任方**,并要求双方在
   报告里各自陈述冲突面(文本邻接还是语义重叠)。
4. 运行时资源(端口、CDP 调试口、主 app)走黑板 `scripts/wt-board.sh` claim
   (规则见 AGENTS.md「并行任务的运行时资源黑板」)。

## 四、任务书(brief)标准

每张任务书必须**自包含**——agent 不读会话历史也能干活(呼应全局文档规范
「干净上下文独立执笔」):

1. 背景与目标;
2. **裁决依据的原文坐标**(文件+行号,不转述);
3. 已知连带(会被触发的硬钉断言、登记机关、计数锁);
4. 并行纪律(worktree 指令、领地边界、邻单在改什么);
5. 门禁清单(指向该仓 AGENTS.md 的门禁节,不另抄一份);
6. 报告格式(要求带第一手证据:先红后绿输出、门禁实测结果、PR 号)。

**已裁事项直接写进任务书,agent 无权再上升**;允许 agent 上升的只有真正的
原则冲突与任务书未覆盖的目标级取舍。TDD 先红后绿是每张实现单的硬要求
(AGENTS.md「Developer Workflow Rules」既有规则,此处只是重申其在派单里的位置)。

## 五、PR 审合管线

1. **PR 开出即押住**:`env -u GITHUB_TOKEN gh pr merge <N> --disable-auto`,
   实施席不许自合。
2. **攒批送审**:攒 2–4 个 PR 打包成一次 codex 调用(降低调用开销与弹窗干扰);
   提示词逐 PR 定制审点,并**显式标注跨 PR 交互面**(两单动同一文件时,
   一方引入的对象会不会让另一方删掉的防线失守)。
3. **codex 裁决不是终裁**:rework 的每条发现由协调方裁定真伪与处方——codex 也会
   错,也会开出与仓内设计真相冲突的药方(先例:2026-09-01 run_dir 词表白名单
   处方被驳回)。真缺陷打回**原实施席**返修,不换人;处方给第一性修法,
   不许逐条打补丁。
4. **本地红先对照 pristine main**:并行期本地测试失败,先在干净 `origin/main`
   同环境复跑同一测试;两边都红=环境/既有问题(记录并继续),只有本 PR 红
   才算本 PR 的问题。
5. **例外:纯记录类 docs PR**(台账更新、裁决落盘、证据归档)不过 codex,
   直接 auto-merge——它们的内容是用户原话与已发生事实的存证,对抗审无靶子。
   涉及规范正文、指针语义、门禁的 docs PR **不在此例外内**,照常送审。
6. 合并按依赖顺序执行;合并后按 AGENTS.md「Workflow Pipeline」第 6/7 条
   跟进根目录依赖与 vendor 重建。

## 六、状态与落盘纪律

1. **唯一状态源** = [DELIVERY_LEDGER.md](DELIVERY_LEDGER.md);裁决落决议文档;
   证据归档进证据包目录。**不在聊天里存任何需要幸存的东西**(会话上下文会被
   压缩,依据:全局规则「方案落盘」与 0009 教训)。
2. 实施席的**界外发现挂 task chip**(或在报告里列明),不许夹进自己的 PR
   (夹带让 review 失焦;呼应 AGENTS.md「一个任务一个 PR」)。
3. 协调方在等待通知的间隙只做编排/落盘类轻活,不与任何在跑单碰同一文件。
4. agent 报告里的"已完成"必须以其报告内的第一手证据为据;协调方转述时
   同样只认证据(报告纪律:没有当轮工具证据不得声称)。
