## 需求 1 — Studio Assets Panel: Subgraph 类目与跨 Skill 导入流程 (2026-05-22)

**PM 原话 (不 paraphrase)**:

> subgraph 有一个配套需求, 在侧边栏的 assets panel 中要加上一个类目叫做 subgraph, 类似图中的 timeline, 可以折叠; 因为 subgraph 的文件不在当前 graph skill 的路径中, 所以需要从注册的 skills 里找到他并显示在 subgraph 的目录里, 如果 subgraph 没有注册, 但是 subgraph.md 写了, 找不到, 那需要在显示位置标红报错, 点击弹出 os 文件管理器选择该 graph skill 进行导入。
>
> 这个需求不是 engine 需求, 但是也与引擎相关, 如果 skill 的注册表全部放在 studio 后端, 那么编译的时候就需要请求后端拿到注册表里的物理地址才能读到文件。

**关联 task**: #50 (frontend 实施) + #51 (engine SkillResolverProtocol DI cutover)
**配套**: Engine V0.3.0 `SUBGRAPH.md` schema + `SkillResolverProtocol` DI (跟 Q9 ModelResolver 同款路径 3)
**未来分发归属候选** (PM 清理时拍): `docs/studio/feature-folders/multi-file-editor/` (assets panel UI 主体) 或 `docs/studio/feature-folders/skill-lifecycle/` (skill 导入流程) 或 `docs/studio/system-level/studio-layout/` (全局 sidebar 不只 multi-file editor)

### 需求拆解 (frontend + backend + engine 三处协同)

**1. Frontend — assets panel 新增 subgraph 类目**

- 位置: Studio sidebar / multi-file editor 左侧 assets panel, 跟现有 timeline 类目同款 collapsible section
- 类目内容: 当前打开的 graph skill 引用的所有 subgraph 入口 (从该 graph skill 内所有 `phases/<name>/SUBGRAPH.md` frontmatter `target_skill:` 字段聚合)
- 渲染规则:
  - **已注册** (studio skill registry 能 resolve `target_skill`) → 显示子 skill 名 + 可展开内部 phase 树 (链接到子 skill 完整目录)
  - **未注册** (registry 查不到) → 标红 + 错误提示 + 点击触发"导入 graph skill"流程

**2. 导入流程 (未注册时)**

- 用户点击标红的 subgraph 入口 → Tauri 触发 OS 文件管理器选目录对话框 (e.g. `tauri::api::dialog::FileDialogBuilder::pick_folder`)
- 用户选中一个 graph skill 目录 (含 `GRAPH.md` 的根目录)
- Studio 后端调 `POST /api/studio/skills/import { directory_path, target_skill_id }`
  - 验证目录含 `GRAPH.md` + 跟 `target_skill_id` (从父图 SUBGRAPH.md 提取) 一致
  - 写入 studio skill registry (`<settings_dir>/Skills/<skill_id>/skill_summary.json` per `apps/studio/backend/app/core/adapters/metadata_local.py`)
  - 返回成功后, frontend reload assets panel, 红色变正常

**3. Engine 接口 (跟 SUBGRAPH.md cutover 同 PR)**

按 PM 拍**路径 3** (`SkillResolverProtocol` DI, 跟 Q9 ModelResolver 同款):

- engine `core/skill_resolver_protocol.py` 暴露 `Protocol.resolve(skill_id) -> Path` (raise `SkillResolutionError` if unregistered)
- studio 后端 `apps/studio/backend/app/services/skill_resolver.py` 实现 `StudioSkillResolver`, 启动期注入 engine
- engine `graph_assembler.py:147` `_resolve_sub_skill_path` 改 `skill_resolver.resolve(phase_ast.target_skill)`
- 失败时 engine 抛 `SkillResolutionError`, 沿 trace 发结构化错误码 `F-v3-skill-not-registered` (含 `target_skill_id`), Studio frontend 收到后渲染红色 + 导入入口

### 不属于本需求 (PM 后续可能扩展)

- 主动浏览 studio skill registry 的"全局 skill 库 panel" — 本需求只覆盖**当前 graph skill 引用的 subgraph 入口**, 不是 skill 库全景
- subgraph 双向反查 ("这个 skill 被哪些 graph 引用") — follow-up
- subgraph 版本管理 / 跨版本兼容 — follow-up
