## 如果按「功能模块垂直闭包」重整,先动这三个域

**1. LLM Registry / Provider 域(最优先)**
覆盖 S1-1、S1-3、S2-13、S2-14。这是全仓唯一的"孤峰式"耦合体:`routers\llm.py` 6717 行 + `services\llm_*.py` 7 个文件 + gateway `registry/`+`call/`+`probing/`+`dialect/` 四个包,而 base_url 规范化(7 owner)、protocol 分支(20 处)、能力推断、证据合并四条业务规则**同时在 studio 和 gateway 两侧各有一套**。先动它的理由是收益/风险比最高:base_url 与 protocol 判别式是纯函数,可以先在 gateway 收敛成单一 owner(`canonicalize_base_url` 吸收 `apply_call_method_base_url`/`VersionedPath`/`fingerprint._normalize_base_url`),再把 llm.py 里的能力推断/证据合并整块下沉成 gateway 的 `capabilities` 子域 —— 这一步能直接砍掉 llm.py 一半体量,且不触碰任何 IO。

**2. Run / Artifact 生命周期域**
覆盖 S1-4、S2-11、S2-9、S2-6。`run_id` 的合法性、run 目录布局、artifact 引用是同一个域的三个面,现在被切在 `routers\runs.py`(不校验)/ `services\run_manager.py`(1242 行 god class)/ `adapters\run_artifact_store_local.py` / `adapters\runtime_state_store_local.py` / `services\skills.py`(路径函数 :1499-1539)五处。垂直闭包的做法是:把 run_id 提成一个在 router 入口就构造的类型(`RunId` NewType/Pydantic 约束),让 4 份校验塌缩成 1 份并前移到边界 —— 这同时解掉 S1-4 的 fail-late 和 S2-11 的一部分职责膨胀,且改动面是机械的、可被现有测试覆盖。

**3. Skill 源文件读取与编译诊断域**
覆盖 S1-2(正向泄漏)、S2-8、S2-6。skill index 读取 4 份、frontmatter 解析 3 份、BOM 处理 2 份平行实现,根因是**engine 把 `_parse_frontmatter` / `_predict_internal` 设成私有,却没提供等价公开 API**,studio 只能复制或伸手。按 AGENTS.md:293-298 的"Boundaries, not locks",正确动作是在 engine 侧把 frontmatter 解析、skill index 解析、golden diff 原子提升为公开 API,再删掉 studio 的 4+3+2 份影子实现 —— 这是三个域里唯一必须改 SDK 的,但也是唯一能一次性消灭 9 处复制的。放第三位是因为它需要 engine 的 `mypy --strict` + 全量测试门禁,周期最长。
