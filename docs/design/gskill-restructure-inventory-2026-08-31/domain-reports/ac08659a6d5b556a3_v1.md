# 域一：模型供给域

## ① 应然（Effect / own / 概念词表 / 膜 / 北极星）

**一句话 Effect**：把「用户手里的一把 key + 一个 URL」变成「可被角色消费的、带证据的可用模型」，且每一次判定都能说出它凭什么这么判。

| 项 | 内容 |
|---|---|
| **own 的事实** | (base_url, protocol) 格子的身份与凭据；该格子上有哪些 route；每条 route 最近一次被真实询问的结果与证据；role→route 链 |
| **概念词表** | `Endpoint`(格子) / `Route`(格子×模型) / `CallMethod`(该模型的一种官方调用法) / `Dialect`(该 method 的线上语言) / `Probe`(一次真实询问) / `Verdict`(这次询问settle了什么) / `Evidence`(可回放的证据) / `Role`→`FallbackChain` |
| **膜（不可外泄）** | ① provider 的 vendor error code 字符串 ② protocol 分支 ③ URL 拼装规则 ④ LangChain 类型 |
| **膜（不可内渗）** | ① Studio 的 UI 状态词 ② HTTP 状态码语义 ③ 用户"authoring intent" |
| **北极星贡献** | *可靠可重现*：同一 route 无论走哪条通道都发同一个请求 → 探测结果对真实调用有预测力；*去黑盒*：红了能说出「哪个 URL、哪个 method、provider 回了什么」；*本地=服务端*：同一 gateway 包同时被 sidecar 与 embedded executor 消费 |

**目标形状（重整决议）**：gateway 实现新 engine 仓的 `ModelResolver` Port。当前 `ModelResolverProtocol`（`call/protocol.py:26-49`）已是该形状的雏形，但 **两处与目标冲突**，见 ⑥/⑦。

### B. 真正的 404→删路由链条（新发现，替代上条）

**跨协议 URL 污染**：`registry/base_url.py:32-37` 的 anthropic 规范化对 deepseek 主机**追加 `/anthropic`**。于是一个 `anthropic_compatible` × `api.deepseek.com` 的格子，落盘 base_url = `https://api.deepseek.com/anthropic`（`services/llm_credentials.py:185,231`）。而该 endpoint 的 backend 被判为 `"deepseek"`（`registry/call_methods.py:164-168`），其静态探测候选（`app/data/probe_candidates.json:45-53`）第一条就是 **`deepseek_chat_completions`**，`base_url_transform` = `"none"`（`registry/call_methods.json:89`）→ `apply_call_method_base_url` 原样返回 → `VersionedPath("/chat/completions").url()` → **`https://api.deepseek.com/anthropic/v1/chat/completions`**。

后续判决链：
1. 该 URL 404，DeepSeek 未知路径回非 JSON 体 → `probing/judge.py:278-279` `if code == 404 and not _is_provider_error_payload(answer): return "protocol_unsupported"`
2. `probing/wire.py:233` 该通道调 `probe_status(...)` **未传 `probed_backend`**（对比 `:98` 与 `:176` 都传了）→ 外来协议校正被关闭
3. `routers/llm.py:1087-1114`：`last_error_code == "protocol_unsupported"` → **`del latest_credentials.provider_routes[route_id]`** 删掉该 endpoint 上**全部** route，并 `_remove_route_references_from_roles` 剥掉角色引用
4. `routers/llm.py:5226` `_PROTOCOL_UNSUPPORTED_RECHECK = timedelta(days=30)` → 半衰期锁死 30 天，`test_endpoint` 直接跳过（`:804-830`）

**这就是"删 124 条路由"的完整因果**，且它违背应然中最硬的一条：*绝不误伤用户数据*。一次 URL 拼错 → 永久删除用户手工录入的模型 + 角色配置，无撤销、无备份、无 dry-run。

## ⑦ Level-3 模块候选（split-first + 八项义务）

### L3-1 · `UrlPlan`（端点地址计划）

| 义务 | 内容 |
|---|---|
| **为何存在** | 今天 9 个 owner 各答一半"这次该打哪个 URL"，答案不一致且没人拿得到最终 URL。这是 ③B 那条删数据链的第一因 |
| **own 的事实** | (raw_url, protocol, method_id) → 唯一的 `UrlPlan{canonical_base, request_url, version_root, transform_applied}` |
| **公开能力** | `plan(raw_url, protocol, method_id) -&gt; UrlPlan`；`storage_key(plan)`（替 `_endpoint_combo_key`）；`publish_form(plan)`（保留 `evidence_wire` 语义为一个 `form`） |
| **依赖** | 仅 `urllib.parse` + `Protocol`/`CallMethodDefinition` 两个类型 |
| **规则/动作** | 纯函数，无 IO |
| **承诺与失败** | 承诺：幂等 `plan(plan(x))==plan(x)`；同一 (endpoint, method) 的四个通道拿到**逐字节相同**的 `request_url`。失败：raw_url 不可解析 → `UrlPlanError`，**绝不**返回半成品 |
| **证据** | `UrlPlan` 本身可序列化进探测结果 → 直接消灭"证据不记请求 URL" |
| **生命周期** | 无状态；随 `call_methods.json` 版本演进 |
| **合并证据** | 三类全中：分开双 owner（今天就是 9 个）／原子状态转换（规范化+版本对齐+method 变换必须一次算完，中途读到会错）／无独立效果（单拿 `_ark_anthropic_base_url` 无意义） |

### L3-2 · `Verdict`（判定与原因码）

| 义务 | 内容 |
