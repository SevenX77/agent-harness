## 本次 session 的关键设计决策（next-session 必须知道）

### 1. Schema 2.0 三轴模型

读 `src/core/graph_agent/core/manifest.py` 的模块 docstring。简记：

- **artifact 轴**：`type: agent | graph | persona`
- **phase mode 轴**（仅 GraphSkillDef.phases 内）：`mode: llm | logic | delegate`
- **delegation 轴**（仅 LLMPhase 内、互斥）：`subgraph: / sub_skills: / subagent_enabled:`

`SkillManifest = Annotated[Union[AgentSkillDef, GraphSkillDef, PersonaSkillDef], Field(discriminator="type")]` —— Pydantic discriminated union 是结构性校验的唯一来源。`extra="forbid"` 在每个子类上，所以拼写错误的字段会被自动拒绝。

### 2. Loader 单一入口

`load_workflow_from_md(md_path)` 的流程（`src/core/graph_agent/core/loader.py:252`）：

1. `_parse_frontmatter` peek `schema_version`
2. 若 `"2.0"`：跑 `compile_skill`（短路，纯 Pydantic）→ `parse_skill_file` → `TypeAdapter[SkillManifest].validate_python` → 按 `type` dispatch 到 `_phase_from_agent_skill` / `_phase_from_graph_phase`
3. 不是 `"2.0"` → `SkillCompilationError(F-schema-version)` fail fast

### 3. Persona 注入合约（Q2 修复后）

`_inject_persona(persona, system_prompt)` 在 loader.py:436 左右：

```
{persona.role_profile}

---

## 评估标准

{persona.evaluation_rubrics if not None}

---

{system_prompt or ""}
```

- `evaluation_rubrics` 为 None 时跳过中间块
- `few_shot_examples` 非空 → `raise NotImplementedError`（Phase 数据结构没有 messages history 字段；silent drop 会让 PM 在 SKILL.md 里填了 examples 却看不到效果）

### 4. Compiler 现在是 thin shell

`src/core/graph_agent/core/compiler.py` 174 行，**只**做：
- schema_version != "2.0" → `F-schema-version` FATAL
- Pydantic ValidationError → 转成 `F-pydantic` issues
- 其他都不管

**所有 1.x `_check_*` 已删除**。它们绑死在 XML body regex 上，schema 2.0 没 XML body，没复用价值（这个前提 Gemini round-2 接受了）。

### 5. deerflow validation 宽松化（Q5）

`src/core/graph_agent/deerflow/skills/validation.py` 现在只校验它关心的字段（name / description / license / allowed-tools / metadata / compatibility / version / author），**未知字段静默通过**。schema 2.0 的 orchestration keys（schema_version / type / io / phases / agent_profile / ...）通过 discovery layer 不再被拒。`graph_agent.core.manifest.SkillManifest` 是 orchestration keys 的权威校验器。
