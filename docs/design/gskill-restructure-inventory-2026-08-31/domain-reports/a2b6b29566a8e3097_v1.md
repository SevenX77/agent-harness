## ③ 账实不符清单

### A. 「app 起得来」

**A1 · Rust `setup()` 同步阻塞启动,最坏 90s 无事件循环** — 与 D10「壳即时渲染」直接冲突
- 事实:`SidecarSupervisor::start(config)` 在 `setup()` 闭包内**同步**调用(lib.rs:4467-4469),内部 `SidecarManager::start` 循环 `startup_attempts=3` × `wait_for_health(health_timeout=30s)`(sidecar.rs:160-188 / 781-799)。上界 3×30s = **90s**。`app.run()` 在 `build()` 之后(lib.rs:4475-4479),事件循环此前未启动。
- 账:`RuntimeGate.tsx:33-35` 注释断言「the app shell renders immediately ("skeleton 就行")… a failed sidecar shows scoped errors, it never hides the whole UI」;`docs/studio/mvp1/03_regions/shell-layout/mvp1-alignment.md:27` 记「2026-08-20 核实 RuntimeShell 无条件渲染 {children}」。
- 不符:两条证词都只核了 **React 层**,没核 **Rust 层**。React 无条件渲染在事件循环起来之后才成立;窗口不可交互的那段时间根本没到 React。
- 加重:失败路径正是最慢路径 —— sidecar 越坏,用户越久看不到 UI。健康路径按 sidecar.rs:76-80 自述冷启 &gt;5s、暖启 1-2s,也已是 1-2s 的白窗。
- ⚠️推断:Tauri v2 中 config 声明的窗口在 `build()` 内创建、`setup` 之后才进 `run()`,故窗口存在但不绘制/不响应。窗口是"白框"还是"未出现"需真机 CDP 采样确认;**代码事实(同步、上界 90s)是确定的**。

**A2 · 兜底 500 无 CORS 头,前端把活着的 sidecar 判死并主动杀掉**(brief 线索,已完整验实,链条 7 环)
1. `register_exception_handlers`(exceptions.py:247-260)**未注册 `Exception`** 兜底。
2. 未捕获异常穿过 `ExceptionMiddleware` → 穿过 auth(BaseHTTPMiddleware 原样上抛)→ 穿过 `CORSMiddleware`(异常路径不加响应头)→ 落到 Starlette `ServerErrorMiddleware`,返回 `text/plain "Internal Server Error"`,**无 `Access-Control-Allow-Origin`**。
3. 打包版 webview origin 是 `tauri://localhost` / `http://tauri.localhost`(config.py:30-31),Tauri dev 是 `http://localhost:5173` → 而 base URL 恒为绝对 `http://127.0.0.1:{port}/api`(sidecar.rs:123)⇒ **一律跨源**。浏览器丢弃无 CORS 头的响应。
4. axios 因此**根本没有 response** → `isBackendUnavailableError` 命中 `ERR_NETWORK`(errors.ts:140-153,`if (error.response) return false` 走不到)。
5. 拦截器派发 `BACKEND_UNAVAILABLE_HTTP_EVENT`(client.ts:156)。
6. `useBackendDownSignal` 的 HTTP 分支无条件 `onDown()`(useBackendDownSignal.ts:89-93),**没有任何"再确认一次 /health"** 的二次判据。
7. `RuntimeGate` 置 `error` + `scheduleAutoRestart()`(RuntimeGate.tsx:168-173)→ `restart_sidecar_automatic` → `SidecarSupervisor::restart_automatic` → `perform_restart` → `Running` 分支 → `SidecarManager::restart` → `post_shutdown` + `kill_process_group`(**sidecar.rs:231-236**)。
- **结果**:一个业务路由的未捕获异常 ⇒ 健康 sidecar 被杀 + token/端口轮换 + 全部在途工作丢失。
- 为什么长期没被发现:纯浏览器 + Vite `/api` 代理是**同源**(vite.config.ts:69-74),500 能收到 → 不触发。只有绝对 base URL 的路径(Tauri dev + 打包)会中。
- 门禁空白:`test_api.py:1349-1381` 两个 CORS 测试**只测 OPTIONS 预检**,从不断言错误响应带 CORS 头。
- ⚠️修复陷阱:`app.add_exception_handler(Exception, …)` **不解决问题** —— Starlette 把 `Exception` 处理器装进 `ServerErrorMiddleware`,那一层在 `CORSMiddleware` **外面**,响应仍不过 CORS。正确修法是在 `configure_cors` **之前**注册一个兜底中间件(使其位于 CORS 内侧),见 ⑧ T1。

**A3 · 一把 Mutex 让 Retry 与 `get_sidecar_config` 排队最长 90s**
- `perform_restart` 在整个尝试循环期间持 `self.state` 锁(sidecar.rs:473),循环上界 3×30s=90s。
- `get_sidecar_config`(lib.rs:1257 → `runtime_config()` → sidecar.rs:421)、`recent_stderr()`(:500)、`shutdown_blocking()`(:507)争同一把锁。
- `restart_sidecar_automatic` 是**同步** `fn`(lib.rs:1317),阻塞 Tauri 命令线程。
- 账实不符:sidecar.rs:317-320 断言「A manual `restart()` is therefore ALWAYS attempted … so pressing Retry is never a dead click」。字面为真(不被预算拒绝),但**观感上仍是死点击**:自动尝试在跑时按 Retry 会静默挂起最长 90s,`RuntimeGate.tsx:143` 那次 `restartSidecar()` 的 promise 一直不 settle,banner 停在 `loading`。

**候选 M8 — `CorsOnEveryResponse`(P21)· 判定:❌ 改判为**「规则」+「机制」
- 它没有自己的事实,也没有独立的成功承诺("响应带 CORS 头"是 M6 承诺的一部分)。

**候选 M9 — `ReaderFacingMessage`(P23)· 判定:❌ 改判为**「规则」
- 已有唯一实现 `errorMessage`(errors.ts:260),问题不是缺模块,是**规则缺可执行门禁**(③B8:门禁只认单行 `instanceof Error ?`)。
- 落地:强化 one-error-exit 门禁(AST 级或多模式),并把 4 个现存违规收编。

| 义务 | 交代 |
|---|---|
| 为何存在 | 210 个手抄类型的漂移已实测发生(③D2),且漂移的后果是**功能盲区**(`paused_at` 前端读不到),不是类型洁癖 |
| own 哪些事实 | 生成物本身(`src/api/generated/*.ts`)+ 生成它的 schema 快照 |
| 公开能力 | `npm run gen:api`;CI `--check` 模式 |
| 依赖 | 后端 `/openapi.json`(需先起后端或离线导出 `app.openapi()`)、`openapi-typescript` |
| 规则动作 | 生成物只读,禁止手改;手抄类型只允许存在于"后端不产出"的部分(如 Tauri IPC 形状) |
| 成功承诺 / 失败暴露 | 生成物与后端 schema 一致;不一致时 CI 红,给出 diff |
| 事后证据 | `git diff --exit-code` 于生成目录 |
| 生命周期 | 每次后端 model 变更 |
- **合并证据**:P24+P25 拆开则**无独立可验证效果** —— 只生成不门禁 = 立刻腐坏;只门禁不生成 = 无基准可比。合法合并。

**模块**:M1 `SidecarProcess` · M2 `SidecarSupervisor` · M3 `RestartBudget` · M4 `BackendLivenessSignal` · M6 `ErrorEnvelope` · M7 `ReasonCodeRegistry` · M10 `ApiContractCodegen`
