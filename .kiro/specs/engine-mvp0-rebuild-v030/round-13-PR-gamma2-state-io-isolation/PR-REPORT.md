# PR γ2 State/IO Isolation 报告

署名：Codex / a1
日期：2026-05-25
状态：已完成，已通过最终质检

## 1. 设计是什么

PR γ2 解决的是一个状态混乱问题：过去一个技能流程运行时，外部输入、每一步产出、临时草稿容易混在同一块共享状态区里。这样会带来三个风险：后面的步骤可能误改最初输入；两个步骤可能把同名结果互相覆盖；子流程可能看到父流程不该暴露的中间内容。

本轮设计把运行状态拆成三个区域：

- 只读输入区：只放流程启动时的外部输入，后续步骤不能改。
- 各步骤产出区：每一步完成后，把自己的结果归档到自己的名下，来源清楚，不互相抢位置。
- 草稿区：只放临时计算内容，不能默认传给后续步骤或子流程。

这个设计的业务价值是：输入来源稳定、步骤产出可追踪、草稿不外泄、子流程像独立黑盒一样运行。它不是为了让流程更复杂，而是为了让每条数据从哪里来、到哪里去都能被判断和审计。

## 3. 完成后功能逻辑

现在一个技能流程启动时，外部输入先进入只读输入区。每个步骤运行前，系统会给它准备一份局部视图：它能看到原始输入，也能看到同一流程里前面步骤已经产出的业务字段；但它看不到上一轮对话消息，也看不到别的步骤的临时草稿。

步骤完成后，结果不会再散落到共享状态区顶层，而是归档到“这个步骤自己的产出区”。如果同一个步骤试图写两次，或者写入不该写的字段，系统会直接报错，避免悄悄覆盖。

同一流程内，后面的步骤可以读取前面步骤的正式产出。例如“分段”步骤产出的摘要，可以被“复核”步骤继续使用。这是横向步骤流转。

子流程和子代理则走另一条规则：它们只接收明确传入的内容，从空产出区、空草稿区、空消息开始运行。父流程的草稿、历史消息、已有产出不会自动进入子流程。这保证子流程可复用，也防止父流程内部状态泄漏。

参考文件读取也被放进独立沙盒里运行。它只拿当前技能、当前步骤和要读的参考文件信息，不继承父流程共享状态。默认超时值固定为 60 秒，后续可以在这个基础上补真正的强制中断和完整追踪。
